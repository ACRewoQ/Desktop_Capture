# V6 プレビュー再生の遅延（技術検証フェーズ1）

**結論：合格。** Media Foundation のハードウェア復号 → D3D11 テクスチャ → Qt Quick 画面への貼り付けで、映像の生成から画面の表示（Present）までの遅延は **p50 約16ms・p95 約24ms（1080p60）**、**p50 約26ms・p95 約34ms（720p30）** でした。目標の 200ms を大きく下回ります。ソフトウェア復号でも p50 約19〜28ms で、どちらを既定にしても遅延は問題になりません。既定はハードウェア復号とし、失敗したらソフトウェア復号に切り替えます。

計測日：2026-10-22（Reo の PC、結果フォルダー `build\v6-results\20261023-023336`）

## 計測環境

| 項目 | 内容 |
|---|---|
| PC | RewoQsGALLERIA2（24 論理コア） |
| GPU | NVIDIA GeForce RTX 5090（ドライバー 32.0.16.1656）、ほかに Meta Virtual Monitor |
| OS | Windows 11 Home 25H2（ビルド 26200） |
| ディスプレイ | 2560x1440 1 枚 |
| Qt | 6.10.3 msvc2022_64（D3D11 RHI、threaded render loop） |
| エンコーダー | NVIDIA H.264 Encoder MFT（テスト用の送り手。本番はレーンBの FFmpeg） |
| デコーダー | Microsoft H264 Video Decoder MFT（hw = D3D11/DXVA、sw = ソフトウェア） |

## 結果

遅延は「テスト映像を作った時刻」から「そのフレームを含む画面の Present（`QQuickWindow::frameSwapped`）」まで。モニターに光が出るまでは、さらに 1 リフレッシュ程度（60Hz で約17ms）かかります。各 20 秒、最初の 120 フレームを除外。

| ケース | p50 ms | p95 ms | max ms | 表示率 | CPU（1コア比） | メモリ |
|---|---|---|---|---|---|---|
| 1080p60 8Mbps hw 復号 | 15.9 | 23.8 | 28.4 | 91.2% | 27% | 146 MB |
| 1080p60 8Mbps sw 復号 | 18.6 | 26.6 | 32.7 | 88.0% | 67% | 135 MB |
| 720p30 3Mbps hw 復号 | 25.5 | 34.2 | 36.2 | 99.7% | 13% | 133 MB |
| 720p30 3Mbps sw 復号 | 27.3 | 35.9 | 40.0 | 99.7% | 20% | 123 MB |
| 720p30 TCP 往復（ループバック） | 26.2 | 34.7 | 39.2 | 99.8% | — | — |
| 720p30 受信側のみ（受信→表示） | 21.4 | 28.7 | 33.0 | — | 6.6% | 122 MB |

CPU はエンコーダー込みの値です（受信側のみの行が、リモコン端末で動く部分に近い値です）。表示率は、60Hz の画面に 60fps を出すときに同じリフレッシュ内で次のフレームに追い越された分が抜けるため 100% になりません（遅延には影響しません）。

### 段階別（1080p60 hw 復号、p50 / p95 ms）

| 段階 | p50 | p95 | 内容 |
|---|---|---|---|
| encode | 7.4 | 10.6 | テスト用エンコード（本番の構成では別物） |
| decode | 0.24 | 0.43 | MF 復号（低遅延モード、1 入力で 1 出力） |
| convert | 0.12 | 0.22 | ID3D11VideoProcessor で NV12 → BGRA |
| copy | 7.0 | 15.7 | 共有テクスチャ公開 → Qt の描画タイミングでコピー（描画待ち） |
| present | 0.13 | 0.32 | コピー → Present |

遅延の大半は「次の描画タイミングまでの待ち」（copy）で、平均で半フレーム、最大で 1 フレーム分です。720p30 では copy が約20ms になります。これは、Qt の VBlank スレッドを無効にした（下記）ためにタイマーでペーシングされているためと考えられます。どちらにしても目標には十分な余裕があります。

### 正しい映像が届いていることの確認

各フレームの左上にフレーム番号のバーコードを焼き込み、デコード側（変換直後）と表示側（Qt に渡すテクスチャ）でテクスチャを読み戻して照合しました。全ケースで **一致 100%（不一致 0）**。

ソフトウェア復号は 1080p60 で 1 コアの約 67%（全体の 3%）を使います。RAM 4GB のリモコン端末では、ハードウェア復号を既定にします。

## 分かったこと（後のレーンへの申し送り）

1. **Qt 6.10 の VBlank スレッドが、この PC では動かない。** `QWindow::requestUpdate()` のペーシングに使う DXGI VBlank スレッド（QDxgiVSyncService）が VBlank を返さず、ウィンドウが最初の 1 フレームで止まります。起動ログに `Unable to open monitor interface to \\.\DISPLAY1 ... 0xe0000225` が出ます（Meta Virtual Monitor ドライバーの影響の可能性）。環境変数 `QT_D3D_NO_VBLANK_THREAD=1` で解消します。**レーンCの UI でも、QGuiApplication を作る前にこれを設定する必要があります**（V5 の計測でも同じ症状を確認済み）。
2. **デコードは Qt とは別の D3D11 デバイスで行い、共有テクスチャ（NT ハンドル + キード ミューテックス）で渡す。** Qt の immediate context をデコーダーのスレッドから触らずに済みます。コピー 1 回（1080p で 0.1ms 未満）で済みます。
3. **Qt 側の D3D オブジェクトの寿命は Qt に合わせる。** 表示用テクスチャは Qt に `QRhiTexture` として作らせ（`createTextureFromRhiTexture` は QRhiTexture の所有権を取る）、共有テクスチャを開いた側のオブジェクトはシーングラフのノードに持たせて Qt のレンダースレッドで破棄させます。共有テクスチャを作ったデコード側デバイスはウィンドウより後に破棄します。これらを守るまで、終了時に不定期のクラッシュが出ていました（最終版は 28 回の連続実行で 0 件）。
4. **MF の低遅延設定。** デコーダーは `MF_LOW_LATENCY` と `CODECAPI_AVLowLatencyMode` を受け付け、バッファリングしません。NVIDIA のエンコーダー MFT は `AVLowLatencyMode` と B フレーム数の設定を拒否しますが（0x80070057）、実際の出力は入力 1 枚につき 1 枚で遅延は増えていません。
5. **`QQuickWindow::grabWindow()` には外部 D3D11 テクスチャが写らない。** 画面の自動スクリーンショットで目視確認する方法は使えないため、上記のバーコード照合で確認しました。GDI の画面キャプチャも flip-model のウィンドウは黒くなります。
6. 隠れたウィンドウは描画が止まる可能性があるため、検証ツールは最前面で表示します。

## ツールと再現手順

`tools/v6_preview/`（Windows のみ）。Qt が見つからない場合は `dc-v6-bench` だけがビルドされます。

| 実行ファイル | 内容 |
|---|---|
| `dc-v6-bench` | 画面なし。テスト映像 → エンコード → 復号 → 変換までを 1 プロセスで計測。`--send HOST:PORT` で別 PC の受信側へ送り、往復遅延を計測 |
| `dc-v6-preview` | Qt Quick（D3D11）で表示まで計測。`--listen PORT` で受信側になる（リモコン端末で実行） |

```powershell
cmake --preset windows
cmake --build --preset windows-release --target dc-v6-bench dc-v6-preview
.\scripts\v6-measure.ps1            # 全ケース（約3分）。結果は build\v6-results\<日時>\
```

主なオプション：`--size 1280x720 --fps 30 --kbps 3000`、`--decoder hw|sw`、`--encoder auto|hw|sw`、`--seconds N`、`--csv FILE`（フレームごとの段階別時間）。

別 PC での計測例（リモコン端末で受信、メイン PC から送信）：

```powershell
# リモコン端末
dc-v6-preview.exe --listen 47860 --size 1280x720 --fps 30 --seconds 40
# メイン PC
dc-v6-bench.exe --send <リモコン端末のIP>:47860 --size 1280x720 --fps 30 --kbps 3000 --seconds 30
```
