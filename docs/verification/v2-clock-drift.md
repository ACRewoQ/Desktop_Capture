# 技術検証 V2：クロックズレ補正

**問い**：別々のクロックで動く 2 台のオーディオデバイスを可変レートリサンプルで合わせたとき、1 時間でズレ（遅延の変化）とプチノイズが出ないか。

**結論**：（実機結果を記入）

## 方式

A2「複数デバイス」でエンジンが使う方式そのものを `libs/clocksync` に実装した。

```
デバイスA（入力側のクロック） → FIFO → 可変レートリサンプラー → デバイスB（エンジン／出力側のクロック）
         └ パケットの時刻(QPC) → DLL ┘        ↑ 比率
                                FIFO 量の誤差 → PI 制御
```

| 部品 | 内容 |
|---|---|
| `TimeDll` | A のパケット時刻（QPC）から「時刻 t における A のフレーム位置」を推定する 2 次 DLL（帯域 0.1 Hz）。パケット単位の到着による鋸歯状の揺れとタイムスタンプのジッターを除く |
| `DriftController` | B のブロックごとに「A の推定位置 − 読み出し位置」を FIFO 量とし、開始時の値を保つ PI 制御。最初の 15 秒は帯域 0.05 Hz で素早く合わせ、30 秒で 0.01 Hz に絞る（ピッチの揺れを抑える）。比率は ±2000 ppm で制限 |
| `VariableResampler` | Kaiser 窓 sinc（64 タップ、512 位相の線形補間、通過域 〜19 kHz、阻止域 約 −100 dB）。比率はブロックごとに変えられ、位置は連続なので切替でノイズが出ない。各位相の DC 利得を 1 に正規化 |
| `ClockBridge` | 上記をまとめた SPSC ブリッジ。リアルタイム安全（確保・ロックなし）。アンダーラン／オーバーラン／不連続時は無音で再同期し、学習した比率は保持 |
| `ToneAnalyzer` | 出力の正弦波を 100 ms ごとに 4 パラメーター正弦波フィット（IEEE 1057）し、残差から SINAD を出す。60 dB 未満のブロックをプチノイズとして数える。位相を連続に追い、遅延の変化も測る |

鋸歯状の揺れを時刻で除くのが要点。FIFO 量をそのまま平均すると、2 台の周期のうなり（100 ppm 差なら 0.01 Hz）で数百フレームの偽の揺れが出て、低域通過では取り除けない。

## シミュレーション（`dc-drift-sim`、各 60 分）

真の時刻が分かるモデルで、出力の遅延とノイズを直接測った。全シナリオ合格。

| シナリオ | 条件 | 遅延の変化 | 最小 SINAD | 推定誤差 |
|---|---|---|---|---|
| typical | +40 / −25 ppm、10 ms 周期、コールバック揺れ 2 ms | 7.6 µs | 105.8 dB | 0.02 ppm |
| large-offset | +500 / −500 ppm（1000 ppm 差）、480 / 144 フレーム | 52 µs | 109.0 dB | 0.04 ppm |
| wander | +30 ppm ± 20 ppm（10 分周期の温度変化） | 107 µs | 105.9 dB | 0.09 ppm |
| bursty | −60 ± 5 ppm / +15 ppm、1024 / 441 フレーム、時刻ジッター 1 ms | 305 µs | 81.3 dB | 追従中 |
| same-clock | 同一クロック | 5.3 µs | 106.2 dB | 0.00 ppm |

アンダーラン・オーバーラン・再同期・プチノイズ（SINAD 60 dB 未満のブロック）はすべて 0。

## 実機試験（`dc-drift-test`）

```
トーン → 出力A → Aのループバック（Aのクロック） → ClockBridge → 出力B
                                                        └→ Bのループバック → 解析
```

B のループバックは B が実際に鳴らした音なので、プチノイズと遅延の変化を外から確かめられる。遅延は「B で鳴った時刻 − A でそのトーン位相を出した時刻」を両ループバックの QPC 時刻から求める。

実行方法：

```powershell
.\scripts\v2-drift.ps1 -SimOnly                  # ビルドとシミュレーション、デバイス一覧
.\scripts\v2-drift.ps1 -A 0 -B 2 -Minutes 60      # 実機 1 時間（結果は build\v2\）
```

注意：A と B で小さな 1 kHz（−20 dBFS）が鳴る。スピーカーの音量を下げても測定には影響しない（ループバックはスピーカーの手前）。試験中は A・B で他の音を鳴らさないこと（通知音もプチノイズとして数えられる）。

合格条件：アンダーラン・オーバーラン・再同期 0、B のプチノイズブロック 0、遅延の変化 1 ms 未満（暖機 60 秒を除く）。
