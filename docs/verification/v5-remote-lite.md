# V5 リモコンの軽さ（技術検証）

**結論：合格。** RAM 4GB の実機（Surface、Win11 Pro・Pentium 4425Y・UHD 615・タッチ 10 点）で、Qt Quick の最小ミキサー画面（64 トラック）の常駐メモリは約 91MB（全画面 85MB）、CPU 3〜4% で、G4 の目標 150MB を下回りました。開発 PC では約 81MB です。合成タッチで 10 本のフェーダーを同時に動かせ、ダブルタップの 0 dB 戻しと、フェーダー上からの横スワイプ（一覧のスクロールのみでフェーダーは動かない）も実機・開発 PC の両方で確認しました。部品は QtQuick.Controls ではなく、Rectangle とポインターハンドラーで作る軽量版を採用します（Controls の Slider は押下を独占するためダブルタップが効かない）。描画は D3D11 を既定にし、OpenGL は使いません。

開発計画フェーズ1の V5。Qt Quick の最小アプリで、RAM 4GB の Win11 端末での常駐メモリと、マルチタッチでの同時フェーダー操作を確かめます。G4 の目標は「常駐メモリ 150MB 以下」です。

## 検証アプリ dc-v5-probe

`tools/v5_remote_probe/`。Qt 6 が見つかったときだけビルドされます（`cmake/DcDependencies.cmake` の `DC_HAVE_QT`）。

| 項目 | 内容 |
|---|---|
| 画面 | 横に並んだフェーダーストリップ（名前・メーター・フェーダー・dB 表示・ミュート）と、下端の計測バー |
| `--ui custom` | 既定。Rectangle / Text とポインターハンドラーだけで描いた軽量版 |
| `--ui controls` | 比較用。QtQuick.Controls（Basic スタイル）の Slider / Button / Label で同じ画面 |
| `--ui minimal` | 下限の目安。計測バーだけのウィンドウ |
| `--tracks N` | ストリップ数（1〜64） |
| `--connect HOST[:PORT]` | 模擬ではなく mixd / dc-mock-server に接続。足りない分は `/mixer/track/add` で増やし、フェーダー操作を Set で送り、UDP メーターを受ける |
| `--backend` | 描画方式。`default`（Windows では D3D11）/ `d3d11` / `software` / `opengl` |
| `--touch-test` | 合成タッチによる自動試験を行って終了（下記） |
| `--duration SEC` / `--report FILE` | 指定秒数で終了し、JSON の計測結果を書く |

フェーダーは指を置いた位置からの相対移動で動き（触れた瞬間に値が飛ばない）、ダブルタップで 0 dB に戻ります。横スワイプはストリップ一覧のスクロールになり、フェーダーは動きません。

### タッチ自動試験（`--touch-test`）

Windows では `InjectTouchInput` で本物のタッチ入力を合成するので、タッチパネルのない PC でも確認できます。

1. 10 本の指で 10 本のフェーダーを同時に、指ごとに違う量だけ下げる。全フェーダーが動き、量の順に並び、同時操作数が 10 に達すれば合格
2. フェーダー 1 をダブルタップして 0 dB に戻る
3. フェーダーの上から始めた横スワイプで一覧がスクロールし、どのフェーダーも動かない

試験中はウィンドウを最前面にし、前面でなくなったら合成入力を止めます（他のアプリを誤って操作しないため）。Linux では QTest のタッチイベントで同じ試験を行い、QML 側の動きだけを確かめます。

## 手順

### 1. Qt の導入（初回だけ）

```powershell
.\scripts\install-qt.ps1          # C:\dev\Qt に Qt 6.10 系、環境変数 DC_QT_DIR を設定
```

管理者権限は不要です。aqt 3.3 は Qt 6.11 以降のダウンロード配置を読めないため、既定は 6.10 系です。

### 2. 開発 PC で計測

```powershell
.\scripts\v5-package.ps1          # Release ビルド + 配布用フォルダーと zip
.\build\v5-package\dc-v5-probe\measure.cmd
```

`measure.cmd`（中身は `v5-measure.ps1`）は各構成を 20 秒ずつ起動し、外からワーキングセットと専用メモリ（タスクマネージャーと同じ値）を 1 秒ごとに測ります。後半の平均を定常値とします。結果は `v5-results-日時\summary.csv` と `summary.json` に出ます。

### 3. RAM 4GB 端末で計測

1. `build\v5-package\dc-v5-probe.zip` を端末にコピーして展開（インストール不要。MSVC ランタイムも同梱）
2. `measure.cmd` をダブルクリック。合成タッチ試験の間（約 10 秒×2）は画面に触れない
3. `touch-try.cmd` で全画面表示にし、実際に指で操作する
   - 4〜5 本の指で同時にフェーダーを動かし、計測バーの「最大同時」が指の本数になるか
   - 動きが指に遅れずについてくるか、ダブルタップで 0 dB、横スワイプでページ送り
4. `v5-results-日時` フォルダーを返送

## 結果

### 開発 PC（RewoQsGALLERIA2、2026-10-22）

Win11 Home 25H2（26200）、Core Ultra 9 285K、RAM 32GB、RTX 5090（ほかに Meta Virtual Monitor）、2560×1440・表示倍率 150%、ウィンドウ 1280×800（論理）、Release、Qt 6.10.3。Reo が PC の前で `measure.cmd` を実行（結果フォルダー `v5-results-20261023-072508`）。各 20 秒、後半の平均。

| 構成 | ワーキングセット MB | 専用 MB | fps |
|---|---|---|---|
| minimal（下限） | 75.7 | 98.4 | 1（変化なしで再描画なし） |
| custom 16 本 | 80.7 | 101.5 | 22 |
| custom 64 本 | 80.8 | 101.5 | 22 |
| controls 16 本 | 87.6 | 103.3 | 22 |
| controls 64 本 | 87.8 | 104.3 | 21 |
| custom 64 本・全画面 | 91.2 | 134.7 | 22 |
| custom 64 本・software 描画 | 58.9 | 34.9 | 22 |
| custom 64 本・OpenGL | 131.7 | 173.7 | 22 |
| custom 64 本・モックサーバー接続 | 82.6 | 102.5 | 30 |

CPU 使用率はどの構成も 0.3% 未満（24 コア中）。

タッチ自動試験（32 本、合成タッチ）:

| 試験 | custom | controls |
|---|---|---|
| 10 本同時ドラッグ（全部動き、量の順に並び、同時操作数 10） | 合格 | 合格 |
| ダブルタップで 0 dB | 合格 | 不合格（Slider が押下を独占し TapHandler に届かない。想定どおり） |
| フェーダー上からの横スワイプでスクロールのみ | 合格 | 合格 |

- 大半は Qt Quick + D3D11 の固定分（minimal と同程度）で、ストリップ 64 本の追加分は約 5MB、Controls はさらに約 7MB
- ListView は見えている分しか作らないので、16 本と 64 本でほぼ同じ
- 専用メモリはワーキングセットより大きい（GPU ドライバーの確保分を含む）。全画面では描画先が大きくなり、専用 +33MB・ワーキングセット +10MB
- OpenGL は D3D11 より約 50MB 多いので使わない。software 描画は最も軽い（59MB）ので、端末の GPU ドライバーで問題が出たときの逃げ道になる
- **Qt 6.10 の不具合への対処**：この PC では D3D11 が最初の 1 フレームで止まった（DXGI の VBlank 待ちスレッドが返らない。V6 で特定）。プローブは起動時に `QT_D3D_NO_VBLANK_THREAD=1` を設定する。本番の UI でも同じ設定が必要
- Remote Control から起動したウィンドウは前面に出られないため、タッチ自動試験は PC の前で実行する必要がある（前面でなければ合成入力を止める）
- 実行ファイル一式（Qt DLL・QML・MSVC ランタイム込み）は 50MB、zip で 20MB

### RAM 4GB 端末（Surface TABLET-G9P6077G、2026-10-23）

Win11 Pro 10.0.26300、Pentium 4425Y（2 コア 4 スレッド）、RAM 3.9GB（計測時の空き約 700MB。Claude などが常駐）、Intel UHD Graphics 615、1920×1280・表示倍率 150%、タッチ 10 点。Reo が端末の前で `measure.cmd` を実行（結果フォルダー `v5-results-20261023-202747`）。

| 構成 | ワーキングセット MB | 専用 MB | CPU % | fps |
|---|---|---|---|---|
| minimal（下限） | 80.3 | 46.8 | 0 | 1 |
| custom 16 本 | 89.7 | 54.9 | 3.9 | 21 |
| custom 64 本 | 90.7 | 56.1 | 2.7 | 21 |
| controls 16 本 | 87.8 | 53.0 | 3.9 | 22 |
| controls 64 本 | 89.1 | 54.3 | 2.3 | 22 |
| custom 64 本・全画面 | 84.8 | 55.2 | 3.9 | 22 |
| custom 64 本・software 描画 | 58.6 | 34.9 | 8.7 | 22 |
| custom 64 本・OpenGL | 129.7 | 44.4 | 3.5 | 20 |
| custom 64 本・モックサーバー接続 | 85.5 | 54.5 | 3.9 | 27 |

タッチ自動試験（32 本、合成タッチ）: custom は 3 項目すべて合格、controls はダブルタップのみ不合格（開発 PC と同じ）。どちらも `inject_errors` が 14 あり総合判定は FAIL と出たが、各試験の結果には影響していない（実タッチパネルのある端末では一部フレームの合成入力が拒否される。試験中 44fps）。

- 内蔵 GPU では GPU メモリがワーキングセット側に入るため、開発 PC より専用メモリが小さく、ワーキングセットが約 10MB 大きい
- 全画面のほうが小さいのは、ウィンドウ枠の描画がなくなるためと思われる（差は 6MB）
- fps が 21〜22 に揃っているのは、模擬メーターのタイマーが Windows の 15.6ms 刻みに丸められていたため（33ms → 47ms）。描画負荷ではない。高精度タイマーに修正済み（b0ba273、計測には未反映）。接続時は UDP メーターで 27fps
- software 描画は最も軽いが CPU が約 2 倍なので、既定にはしない
- **Windows 11 のスマート アプリ コントロール**が署名なしの検証アプリ（exe と cmd）を止めた。Reo が端末でオフにして実行した（一度オフにすると再インストールまで戻せない）。配布しない前提なので署名は当面行わない。端末を替えるときは同じ対処が要る
