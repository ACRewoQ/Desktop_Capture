## 何を確かめたか

検証ツール `dc-vst3-probe`（`tools/vst3_probe`）が、mixd と同じやり方でプラグインを 1 本ずつ試します。`scan` は 1 本ごとに子プロセスで動かすので、プラグインが落ちても止まってもスキャンは続きます。

1. 読み込み（`createPluginInstance`）と所要時間
2. バス構成：メインバスをモノ・ステレオに切り替えられるか
3. 音声処理：128 と 256 サンプルで各 1 秒、ブロックごとの処理時間を実時間の予算と比べる。出力に NaN がないか
4. パラメーター一覧：名前・ID・ラベル・段数・現在値の表示文字列など
5. ホストからの操作：値を設定して読み戻す。表示文字列から値に戻せるか
6. 状態の保存・復元：保存 → 値を変更 → 復元 → 元に戻るか。保存し直したバイト列が一致するか
7. プラグイン画面：別スレッドで音声を流したままウィンドウに表示し、閉じる。画面からの操作（パラメーター変更とジェスチャー）がホストに通知されるか

自動テスト（`ctest -R vst3`、3 件）は自作のテスト用プラグイン「DC Test Gain」（`tools/vst3_test_plugin`）で、通常の読み込み、読み込み中のクラッシュ、読み込み中のフリーズを確かめます。3 件とも Windows と Linux で合格。

## 分かったこと（レーンA1・C への申し送り）

1. **プラグインの一覧作り（スキャン）は別プロセスで行う。** 有名なプラグインでも、初回の読み込みでまれに落ちることがありました（Hyperion）。mixd は `dc-vst3-probe scan` と同じ形で子プロセスに調べさせ、結果をキャッシュし、落ちた・時間切れのプラグインは「要確認」として一覧から外します。実行中のプラグインを別プロセスに分けるかは P3 で判断します（設計書の「将来の余地」のまま）。
2. **パラメーターは数万個になる。** 47,137 個のプラグインがあります。プロトコルのスナップショットに全パラメーターを入れず、リモコンが開いたときに必要な分だけ（ページ単位・検索）取りに行く形にします。キーには VST3 の数値 ParamID を使います（再読み込みしても変わらない）。
3. **一覧から外すべきパラメーターがある。** Kontakt の "#000" などのホスト自動化用の空き枠、"Reserved"、MIDI CC・プログラムチェンジ用のもの、表示文字列が空のもの。リモコンのスライダー一覧ではこれらを既定で隠します。
4. **プラグインは自分の表示文字列を値に戻せないことが多い**（46 本中 約 30 本）。リモコンでの数値入力は使わず、スライダー（0〜1 の値）を動かし、表示はプラグインが返す文字列にします。
5. **「連続値」と申告するスイッチがある**（Tracktion の Enable など）。UI は設定した値ではなく、設定後に読み戻した値と文字列を表示します。
6. **状態の復元後、ホストが持つパラメーター値が古いままのことがある**（Surge XT、RetroMod）。プロファイルやスナップショットを読み込んだあとは、少し待ってから全パラメーターを読み直し、差分を UI に配ります。
7. **ホストからの変更は、次の音声処理でプラグインに届く。** 状態を保存する前に音声処理が少なくとも 1 回走っている必要があります。mixd は音声を止めないので通常は問題ありませんが、エンジン停止中の保存では注意します。
8. **読み込みは重い**（最大 1.2 秒）。プロファイル読み込み時は音声スレッドを止めずに、裏で作ってから差し替えます。
9. **画面は大きいものがある**（Surge XT は 2282x1422）。150% スケールでは問題なく表示できました。小さい画面では、はみ出る可能性があるので、ウィンドウを画面内に収める処理を入れます。
10. **JUCE 9 では、画面なしで使える部分（`juce_audio_processors_headless`）と画面ありの部分が分かれた。** プラグイン画面を出すには画面ありの VST3 形式が必要なので、mixd は画面ありの部分もリンクします（設計どおり、画面はプラグイン表示にだけ使う）。

## JUCE の導入方法

- JUCE 9.0.4 を CMake の FetchContent で取得します（vcpkg ではない）。`juce_add_plugin` などの JUCE 独自の CMake 関数がソース一式を必要とするためです。ライセンスは JUCE 8 と同じ AGPLv3 / 商用の二重ライセンスで、個人用なので AGPLv3 で使えます。
- オプション `DC_WITH_JUCE`（既定は OFF）。プリセット `windows-juce` / `windows-juce-release`（出力先 `build\windows-juce`）。初回の取得とビルドで 10 分ほどかかります。
- JUCE は C コンパイラーも使います（`enable_language(C)`）。
- JUCE は `<windows.h>` を自分で設定するので、JUCE を使うディレクトリではプロジェクト共通の定義（`WIN32_LEAN_AND_MEAN` など）を外しています（`dc_juce_directory()`）。自分のコードで `<windows.h>` を読むときは、その前に `NOMINMAX` を定義します（`std::max` が壊れるため）。
- P2 で mixd に JUCE を入れるときは、`DC_WITH_JUCE` を既定 ON にするか、mixd だけ常に JUCE を使う形にします。

## 再現手順

```powershell
cd C:\dev\dc-V7
.\scripts\vst3-probe.ps1                              # 標準の VST3 フォルダー
.\scripts\vst3-probe.ps1 -Dir C:\dev\dc-V7-plugins     # 指定フォルダーだけ
```

結果は `out\vst3\report.md`（表）と `report.json`（詳細）に出ます。1 本ずつ画面が 2 秒ほど開きます。プラグイン画面で操作した変更がホストに届くかは、`dc-vst3-probe gui <plugin.vst3>` で画面を開いて手で確かめられます（変更が 1 行ずつ表示されます）。

ダウンロードした無料プラグイン（インストーラーなしの zip、`C:\dev\dc-V7-plugins`）：Surge XT 1.3.4、Dragonfly Reverb 3.2.10、Airwindows Consolidated（2026-10-17 版）。
