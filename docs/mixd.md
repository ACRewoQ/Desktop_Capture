# 音声エンジン（mixd）

P2 レーンA の骨格。設計書の「device-io」「mixer-core」「control-server」に当たる部分と、録画用の共有メモリ書き出しを持つ。P3 レーン A3 で「recorder」（トラック別録音）と「sampler」を足した。エフェクト・VST3（A1）、プロセス音声（A2）、LAN（N）は別レーン。

## 構成

| ファイル（apps/mixd/src） | 役割 | スレッド |
|---|---|---|
| `controller` | パラメーターツリーの変更を受けてミックス計画とデバイス要求を作り直す。デバイス一覧・入力状態・負荷・音切れ回数の公開、メーター送信、トラックの追加・削除・移動 | 制御（asio） |
| `plan_builder` | ツリーと開いているポートから `MixPlan`（処理順、ルーティング、ソロ、キュー、共有メモリのスロット）を作る純粋関数 | 制御 |
| `engine` | 計画をブロック境界で差し替え、入力ポートから読み、ミキサーを回し、出力デバイスと共有メモリへ書く | 音声（クロック） |
| `mixer` / `dsp` | チャンネルストリップ（Lo-Hi フィルター、フェーダー、パン、センド、キュー）とメーター | 音声 |
| `device_manager` | 要求されたデバイスのストリームを開閉し、クロック基準を選び、切断・失敗から復帰する | デバイス |
| `wasapi_backend` | WASAPI のエンドポイント一覧・変更通知・ストリーム（共有／排他） | 各ストリーム |
| `fake_backend` | テスト用の仮想デバイス（Linux でもエンジン全体を動かせる） | 各ストリーム |
| `recorder` | トラック別録音のテイク：ファイルごとのロックフリー FIFO と書き込みスレッド | 音声（書き込み）、ディスク |
| `audio_file` | 24bit WAV / FLAC の書き出し、WAV / FLAC / MP3 / Ogg Vorbis の読み込みと 48kHz への変換 | ディスク、読み込み |
| `sampler` | パッドの発音（ボイス、モード、バンクごとのバス）と読み込みスレッド | 音声、読み込み |

JUCE はデバイス入出力には使わない。JUCE の WASAPI は入力1台と出力1台を1本のスレッドで組にし、エンドポイント ID も公開しないので、「トラックごとに別の入力デバイス」に合わない。JUCE は P3 のエフェクトと VST3 ホストで使う。

## 音の流れ

```
入力デバイス ─(ストリーム)→ ClockBridge ─┐
                                          ├→ エンジン（クロック基準の出力デバイスのコールバック）
入力デバイス ─(ストリーム)→ ClockBridge ─┘     │
                                                ├→ クロック基準の出力デバイス（直接）
                                                ├→ ClockBridge → 他の出力デバイス
                                                └→ 共有メモリ（capd へ）
```

- エンジンは1台の出力デバイスのクロックで動く。その他の入出力は V2 で合格した `ClockBridge`（QPC で測る PI 制御＋可変レート sinc）でつなぐ。
- クロック基準：`/system/clock_device` → マスターの出力先（1〜8 の順）→ 使われている他の出力 → どれも使えなければ内部タイマー。外れたら次の候補へ自動で切り替え、戻れば元に戻す。今の基準は `/system/clock_active`。
- ブリッジの目標遅延は「(デバイス周期＋エンジン周期)×2＋2ms」。`mixd --bridge-ms` で下限を上げられる（仮想デバイスや USB で音切れするとき）。

## チャンネルストリップ

入力（デバイス＋他トラックからの出力）→ ローカット → ハイカット →［pre：録画・キュー・プリフェーダーセンド］→ フェーダー → パン →［post：出力先・センド・録画］

- フィルターは 2 次バターワース。オン・オフは 10ms のクロスフェード、周波数の変更は滑らかに追従する。
- フェーダー・パン・センド・ミュートは 5ms で滑らかに変化（クリックノイズ防止）。新しいトラックは無音からフェードイン。
- パン：モノトラックは定パワー（中央 −3dB）、ステレオトラックとマスターはバランス。
- ソロ：ソロのトラックと、それに流れ込むトラック・それが流れ込むトラックだけが鳴る。
- キュー：`cue` のトラックのフェーダー前（PFL）を `/cue/target` へ `/cue/volume_db` で送る。
- メーターはフェーダー後・パン前。
- 共有メモリ：`/capture/audio/#/source` のトラックとマスターを書く。`record/tap` が pre ならトラックのチャンネル数、post ならステレオ。

## トラック別録音（recorder）

docs/spec/protocol.md 5.4.2 のとおり。エンジンが自分でファイルに書く（capd は関係しない）。

- 開始時に、録音対象（`record/enabled`）・タップ・チャンネル数を決めて `RecorderTake` を作る。テイクはミックス計画に載り、音声スレッドが毎ブロック、対象の各トラックをファイルごとの FIFO（4 秒分）に入れる。全ファイルが同じブロックから始まり、同じ長さで終わる。
- 書き込みスレッドが FIFO を 20ms ごとに空にしてファイルへ書く。FIFO があふれたブロックは捨てて数え、書き込みスレッドが同じ長さの無音を足す（位置は FIFO の量の分だけずれうるが、長さは保つ）。
- 停止はテイクのない計画を作り、エンジンが採用するのを待ってから（最大 0.5 秒）ファイルを閉じる。
- 録音中に削除されたトラックは無音で続ける。モノ⇔ステレオを変えたときは開始時のチャンネル数に合わせて変換する。
- WAV は 5 秒ごとにヘッダーを書き直す（落ちても途中まで開ける）。4GB を超えると RF64（JUNK チャンクを ds64 に置き換え）。FLAC は libFLAC（圧縮レベル 5）。
- `/recorder/with_capture` が true なら、`/capture/state` が `recording` になったときに始め、`recording` でなくなったら止める（手で始めた録音は録画に関係なく続く）。

## サンプラー

docs/spec/protocol.md 5.4.3 のとおり。

- `file` が変わると読み込みスレッドがファイル全体を読み、48kHz ステレオの float にする（モノは両チャンネルへ、3 チャンネル以上は先頭 2 つ、48kHz 以外は窓付き sinc で変換。ダウンサンプルではカットオフを下げる）。デコーダーは third_party/audio_decoders の dr_wav・dr_flac・dr_mp3・stb_vorbis。
- 読み込んだ音は `SamplerTable`（128 パッドの音・モード・音量）としてミックス計画に載る。押す・離す・止めるはロックフリーのキューで音声スレッドへ届く。
- ボイスは 32。停止・頭出し・音の差し替えは 5ms のフェード。足りなければ一番古いボイスを使う。再生中にファイルを差し替えると、その音は新しい計画の採用時に止まる（古い計画と音が解放される前）。
- 各バンクがステレオのバスに鳴り、`input/kind = sampler` のトラックが全バンクの和か 1 バンクを入力に足す（トラックのフィルター・録音・キューの前）。
- `playing` はメーターと同じ約 30Hz で、変わったパッドだけ配る。

## 共有と排他

`/system/audio_mode`：

- shared：48kHz float で開き、Windows がデバイスのミックス形式に変換する（44.1kHz のデバイスもそのまま使える）。周期はデバイスの既定（通常 10ms）で、`/system/block_size` はエンジン内部の処理単位になる。
- exclusive：48kHz で開ける PCM 形式（float32 / int32 / int24 / int16）を探し、周期を `/system/block_size` に合わせる（デバイスの最小周期が下限）。ドライバーが別のレート（44.1kHz など）に固定していて排他の 48kHz 形式がないデバイスは、そのデバイスだけ共有モードで開き（Windows がレート変換する）、ログに `device note` を出す。他のアプリが排他で使っているデバイスは開けず、`device.error` イベントで理由を知らせる。

排他モードで頼んだ周期どおりに動かないデバイスもある（Steinberg UR22 のドライバーは 128/256 を受け付けるが 10ms ごとにしか起こさない）。各ストリームは最初の 1 秒で起こされる間隔と入力のデータ欠落を測り、合わなければ実際の周期（デバイスの既定周期に近ければその値）で開き直す。それでも駄目なら共有で開く。どちらもログに `device note` を出す。

機器の注意（G2 で分かったこと）：

- 44.1kHz で動いているデバイスを共有モードで使うと、Windows の変換で数分に 1 回データ欠落（DATA_DISCONTINUITY）が出ることがある（UR22 で確認）。デバイスを 48kHz にすると消える。ドライバー側（UR22 は Yamaha Steinberg USB Driver）と Windows のサウンド設定の「既定の形式」の両方を 48kHz にする。レートを変えると Windows はデバイスを別 ID で登録し直す。
- 共有モードの入力は 100ms のバッファで開く（遅延は増えない）。10ms では読み遅れでなくても欠落が出た。
- デバイスの位置（GetBuffer の devicePosition）は、共有モードで変換されるデバイスではデバイス側のレートで数える。

## 録画の開始・停止

docs/spec/protocol.md 5.4.1 のとおり。エンジンは状態（`/capture/state` など）を持ち、実際の録画は capd（role = サービス、名前 `capd`）が行う。`/capture/record/start` で `starting`、capd の `/capture/report state=recording` で `recording`（`elapsed_ms` はエンジンが 250ms ごとに更新）、`stop` で `stopping`、`report idle` で `idle`。録画中に capd が切断すると `error`。

## 試験

- `ctest`：`[mixd]` のテストがフィルター、パン、ミキサー（ルーティング、センド、キュー、ミュート）、共有メモリ、計画（ソロ、入力状態、デバイス要求）、仮想デバイスでのクロック切り替え、制御サーバー越しの結合を確かめる。
- `mixd --fake-devices`：音声ハードウェアなしで UI などから接続できる。
- `[recorder]` `[sampler]` のテスト（tests/test_recorder_sampler.cpp）：WAV / FLAC の往復、リサンプラー、パッドのモード、テイクの長さ、制御サーバー越しの録音とサンプラー。
- A3 の実機確認：`scripts\a3-check.ps1`（`-Minutes`、`-Formats`、`-InputDevice`）。テストトーン入りのマスターと、サンプラー・入力のトラックをフェーダーを動かしながら録音し、全ファイルの長さ・欠落・xrun・トーンの途切れを調べる。続けて Windows の効果音 16 個をパッドに読み込み、各モードの動きを確かめる。
- G2「バッファ128〜256で音切れなし」：`scripts\g2-engine.ps1`（`-Device` で出力、`-WithInput -InputDevice` で入力を選ぶ）。xrun のログ行には時刻、ストリームごとの実測レート、ブリッジの比率、入力欠落の様子が出る。1kHz のテストトーンをマスターに流し、共有モードはループバックの正弦波フィットで音切れを数え、両モードで `/system/xruns`（デバイスの欠落、周期の取りこぼし、ブリッジのアンダーラン）と `/system/cpu_load` を記録する。
