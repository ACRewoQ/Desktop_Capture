# 共有メモリ音声フォーマット仕様 v1

- 状態：**v1 ドラフト（G0 で Reo の確認待ち）**
- 用途：エンジン（mixd）からキャプチャー（capd）へ、録画用の音声を渡す
- 実装：`libs/shmaudio`（`layout.hpp` が構造の定義、`ring.hpp` が書き手・読み手）
- 試験用ツール：`dc-shm-tone write` / `dc-shm-tone read`

`layout.hpp` とこの仕様書を正とします。互換性のない変更では `kVersion` とマッピング名の末尾（`.v1`）を上げます。

## 1. 方針

- エンジンが**唯一の書き手**、capd などが読み手です。読み手は何台いてもよく、書き手は読み手を一切待ちません（音声スレッドを止めないため）。
- 書き込みはロックなし・メモリ確保なし・システムコールなし（時計の読み取りを除く）。
- 全スロット（マスターと各トラック）が**同じフレーム番号**で進みます。読み手は同じ位置を読めば、トラック同士が自動でそろいます。
- 時刻はフレーム番号と QueryPerformanceCounter（QPC）の対応表で表します。映像フレームも QPC で時刻を持つので、マルチプレクサで音と映像をそろえられます。

## 2. 名前と作り方

| 項目 | 値 |
|---|---|
| Windows | `CreateFileMappingW(INVALID_HANDLE_VALUE, …, L"Local\\DesktopCapture.Audio.v1")`（ページファイル裏付け） |
| 読み手 | `OpenFileMappingW(FILE_MAP_READ, …)` で読み取り専用に開く |
| サイズ | 34,091,008 バイト（約 33 MiB、`kLayout.totalBytes`） |
| 名前空間 | `Local\`（同じログオンセッション内のプロセス同士） |

エンジンが先に起動していなければ、capd は 1 秒ごとに開き直しを試みます。capd が開いたままエンジンが再起動した場合、エンジンは既存のマッピングを開き直して初期化し、世代番号（generation）を進めます。

## 3. 配置

すべてリトルエンディアン、x64 の自然なアラインメントです。

| 領域 | オフセット | 内容 |
|---|---|---|
| 共有ヘッダー | 0 | `SharedHeader`（4096 バイト境界まで） |
| スロットヘッダー | `slotsOffset`（4096） | `SlotHeader` × 65（各 64 バイト） |
| 音声データ | `dataOffset`（12288） | スロットごとに `capacityFrames × 2 × 4` = 524,288 バイト |

### 3.1 定数

| 名前 | 値 | 説明 |
|---|---|---|
| `kMagic` | 0x55414344（"DCAU"） | |
| `kVersion` | 1 | |
| `kSampleRate` | 48000 | 固定 |
| `kSlotCount` | 65 | 0 = マスター、1〜64 = トラック番号と同じ |
| `kMaxChannels` | 2 | 1 フレームは常に 2 サンプル分の幅 |
| `kCapacityFrames` | 65536 | 約 1.37 秒。2 のべき乗 |
| `kMaxBlockFrames` | 4096 | 1 回の commit の最大フレーム数 |
| `kAnchorCount` | 64 | 時刻対応表のリングの長さ |

### 3.2 共有ヘッダー（SharedHeader）

初期化後に変わらない部分：`magic`、`version`、`headerBytes`、`slotHeaderBytes`、`sampleRate`、`slotCount`、`capacityFrames`、`maxChannels`、`totalBytes`、`slotsOffset`、`dataOffset`、`slotDataBytes`、`qpcFrequency`、`anchorCount`、`writerPid`。読み手は接続時にこれらが自分の定数と一致することを確認し、違えば使いません。

書き手が更新する部分（すべて 64 ビットのアトミック変数）：

| フィールド | 説明 |
|---|---|
| `generation` | 初期化中は奇数、使用可能なら偶数。エンジンが起動（再起動）するたびに進む |
| `framesWritten` | これまでに確定したフレーム数 = エンジンのサンプル時計 |
| `heartbeatQpc` | 最後に確定したブロックの QPC。止まっていればエンジン停止とみなせる |
| `anchorWriteIndex` | これまでに書いた時刻アンカーの数 |
| `anchors[64]` | 時刻アンカーのリング（下記） |

時刻アンカー（32 バイト）：`seq`（書き換え中は奇数）、`frame`（ブロック先頭のフレーム番号）、`qpc`（そのフレームの QPC）。読み手は `seq` を前後で読み、偶数かつ同じ値のときだけ採用します（シーケンスロック）。

### 3.3 スロットヘッダー（SlotHeader、64 バイト）

| フィールド | 説明 |
|---|---|
| `channels` | 0 = 未使用（読むと無音）、1 = モノ、2 = ステレオ |
| `flags` | bit0 = 入力切断中（中身は無音） |
| `activeSinceFrame` | このスロットが有効になった最初のフレーム。これより前は無音として扱う |
| `label` | `"master"`、`"track/3"` など（診断用、48 バイト、NUL 終端） |

### 3.4 音声データ

- float32、インターリーブ、1 フレーム = 2 サンプル（左・右）。モノのスロットは左だけを使い、右は 0。
- フレーム番号 `f` の位置は `(f mod capacityFrames)`。
- 値は**チャンネルストリップの出力**です。フェーダー前・後のどちらを出すかは録画設定（`/capture/audio/#/source` と各トラックの設定）でエンジンが決めます。

## 4. 書き手の手順（エンジンの音声スレッド、ブロックごと）

1. 録画に使うスロットそれぞれに `write(slot, samples, frames, channels)`（未使用・切断中は `writeSilence`）
2. `commit(frames, qpcOfFirstFrame)`：時刻アンカーを書き、`framesWritten` を release で進める

スロットの割り当て変更（`configureSlot`）は音声スレッド外から行ってよく、次の commit から有効になります。どのスロットを書くかは `/capture/audio/#/source` に従います。

## 5. 読み手の手順（capd）

1. マッピングを開き、`attach()` で定数を検証する。位置は書き手の現在位置から始める
2. 定期的に（例：10ms ごと）`available()` を見て、各スロットを同じ長さだけ `read(slot, …, advance=false)` で読み、最後に `advance(n)` する
3. 戻り値で状況を判断する

| 状態 | 意味 | capd の動作 |
|---|---|---|
| `Ok` | 正常 | そのまま使う |
| `NoData` | 新しいデータなし | 待つ |
| `Overrun` | 読むのが遅れてリングを一周された | `skippedFrames` 分を無音で埋めて時間を保つ |
| `WriterRestarted` | エンジンが再起動した | 位置を合わせ直す。その間は無音で埋める |

- 読んだ直後に `framesWritten` を読み直し、読んでいる間に上書きされた可能性があれば `Overrun` を返してそのデータを捨てます。
- `writerAlive(now, 200ms)` が偽になったらエンジン停止とみなし、録画は無音で続けて時間をずらしません（設計書「デバイス切断時の動作（映像）」の「音声エンジンの停止」）。
- `qpcForFrame(f)` でフレームの時刻を得て、映像と同じ時間軸に置きます。最も近いアンカーから 48kHz で補間します。

## 6. 遅延と余裕

- リング長 1.37 秒に対し、読み手は 10〜50ms ごとに読めば十分な余裕があります。
- 録画では音声を QPC で映像に合わせるので、読み手の読み取り間隔は音ズレに影響しません。

## 7. 将来の拡張

- サンプルレートやスロット数を変える場合は `kVersion` を上げ、マッピング名を `.v2` にします（古い capd が新しいエンジンを誤って読まないように）。
- 仮想マイクを自作ドライバーにする場合（設計書の方式 B）も、同じ形式を流用できるようにしてあります。
